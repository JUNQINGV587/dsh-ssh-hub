# dsh-ssh-hub UI/UX 多角色头脑风暴——统一优化清单

> 生成方式：4 个并行角色子代理（solo-operator 多机运维者 / agent-driver Agent 协作开发者 / occasional-ops 低频运维者 / 视觉与信息设计评审）各自读代码核实后产出提案，本文合并定稿。所有关键论断均已对照源码复核（见各条「佐证」）。
>
> 排序依据：**严重度 = 是否阻断关键任务 × 命中画像权重和**。画像权重：solo-operator 0.5 / agent-driver 0.3 / occasional-ops 0.2；视觉评审为全员服务。权重和 ≥0.5 为 wide。

## 一级 —— 阻断核心工作流（先修）

### U-1 会话清单入口崩溃：未放置会话既看不见也杀不掉
- **命中**：全部画像（覆盖 1.0）｜**用户会遇到什么**：点窗口右上角「Widgets」按钮或空态的「打开侧栏放入会话」，整个窗口主体变成「终端窗口遇到问题」错误卡片，重试依旧。关掉的会话其实还在后台跑（这是设计），但唯一的找回/终止入口就死在这个面板里——既看不见它，也无法主动结束它，只剩删服务器或等 30 分钟静默回收。
- **根因（AI 视角）**：`client-main.tsx:2099` 使用 `<RightSidebar>`，src 与构建产物 `lib/client.js:11334` 均无定义（git 224ac8b 移除定义时漏删引用）；`killSession` 只接线到该组件（2105）；`.dmsListPanel` 系列 CSS 为孤悬样式（287-302）。
- **建议**：补回或重写右侧栏（服务器列表 + 全部会话列表，行内状态点、放回「当前组合/新标签」、终止按钮）；修复前先隐藏崩溃入口；终止会话的入口不要只依赖侧栏（标签 hover 也可终止）。

### U-2 并排监控不可达：无任何创建组合的入口，且组合视图本身无样式
- **命中**：solo-operator 0.5 + agent-driver 0.3（覆盖 0.8）｜**用户会遇到什么**：想 4 台并排盯，每个新会话都独占全屏成为新标签；拖标签合并、新建组合按钮、Alt+d 分屏全都不存在。即使通过旧状态遗留了一个「组合」，它也是一列裸文本堆叠——没有边框、没有间距，分隔条和方向按钮无法操作，块徽标飘在窗口左上角。
- **根因**：`merge`/`ungroup` 纯函数在 `group.mjs` 就绪但**未导入**；`addMember`/`reorderMember`/`swapMembers` 导入后**零调用**；`connectTo` 恒新建标签（1948-1951）；拖放处理器为零（7 种放置位 CSS 是孤悬遗产，256-271）。`.dmsItemsEmpty`/`.dmsWsView`/`.dmsWsMember`/`.dmsGroupDivider`/`.dmsWsOrient` 在 JSX 中使用（1406-1533）但 CSS 模板（66-310）**无任何定义**。
- **建议**：接线 `merge`（标签拖到标签上合并）+ 服务器选择器「加入当前组合 / 新标签」双落点 + 补齐组合视图与空态样式（复用旧 `.dmsEmpty` 的做法）。

### U-3 失败与断线恢复体系缺失：英文 alert / 静默断线 / 主机密钥死胡同
- **命中**：全部画像（覆盖 1.0，occasional-ops 受害最深）｜**用户会遇到什么**：连接失败弹浏览器原生警告框，内容是 `All configured authentication methods failed` 这类英文，没有「重试」「编辑服务器」按钮；终端用着用着断线，标签变红但没有原因、没有重连入口；打开「严格主机密钥校验」后全部连不上，没有任何「接受指纹」的选项，只能把校验关掉。
- **根因**：`window.alert` 直出 ssh2 英文（1952-1954、1002）；WS 只建一次、onclose/onerror 只改状态点（574-599）；`.dmsErr` 终端错误面定义了但从不渲染（123）；`strictHostKeyChecking` 二选一无交互（connection.ts:64-67）；host 有 `exitDetail`（index.ts:215-226）但前端 `TermTab` 不承载（426-432）。
- **建议**：窗口内错误面（分类人话 + 「重试 / 编辑服务器」动作）+ WS 断线指数退避自动重连（host 的 scrollback 重放已就绪，重连不丢上下文）+ 首次连接主机指纹确认。

### U-4 Esc 焦点陷阱：放大/最大化后按 Esc 退不出，按多了整个窗口消失
- **命中**：agent-driver 0.3 + solo-operator 0.5（覆盖 0.8）｜**用户会遇到什么**：Alt+m 放大某块或 Ctrl+Alt+` 进全屏后按 Esc 没反应（焦点在 xterm 隐藏输入区，Esc 直接进 shell，vim 会收到）；反过来在非输入焦点时按 Esc，一次退放大、两次退最大化、三次直接收起整个窗口——层级不可见，误触代价是失去整个视口。
- **根因**：`client-main.tsx:1789-1795`（INPUT/TEXTAREA 早退 + Esc 三态链）、657-668（active 时 `term.focus()`）、`build.mjs:163`（Escape 直接 return）。
- **建议**：放大/最大化时顶部常驻「按 Esc 还原」提示条；Esc 只负责「退出一层」，「关闭窗口」仅保留 ✕ 或首次 Esc 时 toast 确认。

### U-5 关闭/收起与「会话仍在运行」的心智差异零可见性
- **命中**：全部画像（覆盖 1.0）｜**用户会遇到什么**：关标签以为命令停了，其实 shell 还在服务器上跑且界面无任何提示；收起窗口后无人查看的会话进入 30 分钟静默回收倒计时，回来发现监控标签全没了，说不清是自己关错了还是系统干的；想真杀一个会话却找不到任何按钮（唯一入口在崩溃的侧栏里）。
- **根因**：`closeTabAt` 只移除项无反馈（1844-1851）；Esc/收起即 detach 启动 30 分钟回收计时（registry.ts:60-76，默认 `index.ts:37`）；`killSession` 唯一接线在崩溃侧栏（2105）；删除服务器才有确认（996）。
- **建议**：关标签/移除成员时非打断式提示「会话仍在运行，已放入未放置列表」（附「立即结束」）；窗口常驻「后台会话 N」计数；回收前显示「即将回收」；结束时二次确认，把「关闭」与「结束」在语义与视觉上分开。

## 二级 —— 状态可见性与注意力桥梁（本轮做）

### U-6 无「新输出」提示（注意力桥梁缺失）
- **命中**：agent-driver 0.3 + solo-operator 0.5（0.8）｜**用户会遇到什么**：Agent 在跑 `tail -f` / 部署日志，自己正盯着对话区读汇报——那台机器已滚出几十行，但窗口失焦、切到别的标签后没有任何闪烁或角标提示「这里有新输出」，只能靠猜。
- **根因**：`ws.onmessage` 直接 `term.write`（585-592），无 unread/activity 记录；状态点只有 connecting/live/closed 三态（274-277）。
- **建议**：标签/块加「最近有输出」脉冲点或未读行数角标（窗口聚焦时清除）；可加「盯住（watch）」标记。

### U-7 单标签与窗口层面没有会话状态呈现
- **命中**：全部画像（1.0）｜**用户会遇到什么**：单会话全屏标签只有名字和 ✕，SSH 断了标签栏看不出来，点进去才发现 shell 已退出；窗口也没有「N 在线 / M 断开」的汇总。
- **根因**：`stateLabel` 算好了没渲染（1991）；`dmsTabDot` 样式备好了没用（99-102）；状态点只存在于组合成员徽标（274-277）和孤悬的清单行样式（300-301）。
- **建议**：标签栏恢复状态点；全屏单标签也渲染块徽标；窗口标题区渲染会话汇总。

### U-8 布局与会话的持久化缺位（重启即丢）
- **命中**：solo-operator 0.5 + agent-driver 0.3（0.8）｜**用户会遇到什么**：host 重启后内存里的布局和会话一起没了，回到「还没有会话」且无任何说明；就算 host 没重启，只要布局被清空，重开面板也只自动放回第一个会话（1702-1705），其余得一个个捞。
- **根因**：会话纯内存 + 30 分钟回收（index.ts:37、registry.ts）；布局存 host 内存 `/workspace`（useWorkspaceState 1224-1271，ADR-0007 不落盘）；窗口位置反而持久化在 localStorage（1538-1561）。
- **建议**：布局（不含密钥）落 localStorage，提供「恢复上次布局」一键按序重连；检测到「上次有 N 个会话现已不存在」时显示说明条。

### U-9 快捷键承诺与行为脱节
- **命中**：solo-operator 0.5 + agent-driver 0.3（0.8）｜**用户会遇到什么**：设置卡里能配 8 个动作，实际只有 4 个生效（splitH/splitV 是死键）；Alt+w 写着「关闭块」，按下去却把整个组合解散、所有会话掉回清单；Alt+m 想放大正在看的那块，永远放大第 0 块。
- **根因**：keydown 只处理 newTab/closeTab/closeBlock/magnify/F2/Alt+1-9（1788-1830）；closeTab/closeBlock 都调 `removeTab` 整体移除项（1806-1811，group.mjs:199-204）；magnify 固定 `setMagnifiedMember(0)`（1815）；默认 toggleWindow Ctrl+Shift+` 列在 DSH 已知冲突名单（keybind.mjs:38-55）。
- **建议**：引入「聚焦成员」概念，Alt+w 只关当前块；实现或移除 splitH/splitV；Alt+m 放大当前聚焦成员；默认值避开冲突名单。

### U-10 首次使用引导整体指向坏入口
- **命中**：occasional-ops 0.2 最重，但空态是全员第一屏（1.0）｜**用户会遇到什么**：第一次打开窗口只看到「还没有会话 → 打开侧栏放入会话」，点了就崩；「添加服务器」藏在纯图标齿轮里；README 承诺的「新会话」主按钮不存在。
- **根因**：两个空态都导向 `openSidebar`（1404-1423）；齿轮仅图标（2068）；`ServerPicker` 实现完好（2154-2209）但 `setPicker(true)` 从未被调用（只有 1943 的 false）。
- **建议**：空态按状态分岔（无服务器→「添加第一台服务器」/ 有服务器→直接列出连接 / 有后台会话→「恢复 N 个后台会话」）；工具栏加「＋ 新会话」主按钮；齿轮配文字标签。

### U-11 失焦变暗是死代码（系统状态可见性承诺失效）
- **命中**：全部画像（1.0）｜**用户会遇到什么**：CONTEXT/README 把「失焦只淡化窗框」当卖点，但窗口失焦后几乎看不出变化——只有终端区边缘一圈 1px 描边，无法凭视觉判断键盘输入会进终端还是进旁边的对话。
- **根因**：`.dmsWin.isBlur` 规则选择器指向不存在的 `.dmsWinBar/.dmsWinTool`（192），实际 JSX 元素是 `.dmsWinTabs/.dmsWinActions`（2008/2064）。
- **建议**：规则改绑到实际元素（opacity .55，保留终端区可读性），0.15s 过渡、尊重 reduced-motion。

### U-12 状态点颜色-only 且浅色下不可读
- **命中**：全部画像（1.0）｜**用户会遇到什么**：三态（连接琥珀/在线绿/断开红）只用颜色区分，色弱（约 8% 男性）无法分辨；浅色终端下绿色「在线」点几乎糊掉（对比度约 1.56:1）。
- **根因**：硬编码 `#2ee62e`/`#e8b339`/`#e74856`（274-277、99-102）；对比度脚本只覆盖 xterm 调色板（check-contrast.mjs:15-18），chrome 状态点无门槛。
- **建议**：颜色随 `--dmst-*` 终端主题变量走（浅色用深绿/深红/深琥珀，≥3:1）并纳入检查脚本；叠加形状维度（实心点/空心环+脉冲/叉）或文字兜底。

### U-13 块级双主题边界破裂
- **命中**：全部画像（1.0）｜**用户会遇到什么**：深色界面里把终端固定成浅色后，块与块的分隔边框几乎看不见，整片块像一张白纸拼在一起、网格结构消失，块徽标也近乎隐形。
- **根因**：块边框/活动高亮/徽标用 Wave 调色板（`--wave-border`/`--wave-accent`/`--wave-secondary`，252-254、272），块面用终端主题（`--dmst-bg`）——双主题边界（ADR-0002）在块这一层泄漏。
- **建议**：块级 chrome（边框/活动环/徽标）改走 `--dmst-*` 终端主题令牌，`--wave-*` 只留给窗口框架与标签栏。

## 三级 —— 效率放大器与打磨

- **U-14 无并排/吸附形态**：悬浮窗盖住对话，「左边读对话右边盯终端」每次手动摆。建议加吸附模式（一键贴右半屏/左下角并记忆）或恢复轻量 in-flow 条。（agent 0.3 + solo 0.5，0.8）
- **U-15 组合内无键盘跳转**：Alt+1-9 只切顶层标签，跳不到组合成员。建议成员聚焦态 + 组合内 Alt+1-9 映射成员。（agent 0.3 + solo 0.5，0.8）
- **U-16 多机广播缺失**：对 4 台跑同一命令只能一台台开、一台台敲。建议成员多选「发送到所选/全部」+ 广播前确认。（solo 0.5）
- **U-17 块标识信息层级不足**：徽标只有点+名、无截断，两块分不清谁是谁。建议两段式（常驻：状态点+名称；hover 展开：IP/启动时间/最近活动）+ 稳定色点 + 上滚时「回到底部」。（solo 0.5）
- **U-18 会话无颜色/标记、命名无区分度**：同一台服务器开两个会话标签同名。建议服务器稳定色点 + 同服务器多会话自动后缀（目录/序号）+ 改名持久化。（solo 0.5 + agent 0.3，0.8）
- **U-19 主题生效状态不透明**：点主题按钮不知道实际生效深/浅；本地覆盖总是赢过设置卡默认且无提示。建议点击后短暂显示「已生效：深色」+ 状态小字；三层优先链（本地覆盖 > 全局默认 > 界面）显示当前由谁拍板。（全员，1.0 影响低）
- **U-20 表单「继承全局默认」不可见**：strictHostKey 下拉的「继承」不显示当前实际值，留空不知道会怎样（超时/Keepalive 的占位符却会显示默认值，不一致）。建议下拉或旁注显示生效值。（occasional 0.2）
- **U-21 Auth Kind 术语有门槛 + 切换静默清凭据**：「SSH Agent」「无认证」无解释；从密码切到密钥会静默清掉已存密码（store.ts:106 `sameKind`）。建议选项带场景说明 + 切换时提示「将清除已保存的密码/密钥」。（occasional 0.2）
- **U-22 设置卡「管理服务器…」是空操作**：派发 `dsh-ssh-hub:open-servers`（settings-card.tsx:471）但全仓库无人监听，点了像空气。建议按 spec 落地跨面跳转（打开窗口并弹出抽屉），不可用则提示。（occasional 0.2）
- **U-23 文案残留旧概念**：侧栏入口 title「SSH 终端（专注视图）」是 ADR-0005 旧概念，打开的是浮动窗口；窗口内齿轮/主题/列表全是纯图标按钮。建议统一「SSH 终端窗口」文案、关键入口给文字标签。（occasional 0.2）
- **U-24 README 与 UI 漂移**：README 描述「新会话按钮」「会话清单（工具栏打开）」「n-tree 分割树/7 种拖放」，界面是扁平「标签=会话+组合」模型，查文档反而更困惑。建议 UI 修复后同步文档并注明现行模型。（occasional 0.2）
- **U-25 窗口拖动/缩放手柄隐蔽**：只有标签栏缝隙可拖（拖到标签上不响应）、右下角 8px 半透明角标。建议可见把手区 + 12-14px 命中区 + hover 高亮。（全员，1.0 影响低）

## 整体判断

1. **最痛的不是「缺功能」，而是核心路径实际是坏的**：U-1（清单崩溃）、U-2（并排搭不起来）、U-4（Esc 出不来）是三条把工作流整体截断的一级问题，且都是「重构漏接线/漏删引用」类技术债（`RightSidebar` 漏删、`merge` 未接线、新视图没带 CSS、失焦规则指向旧元素），修复成本低、收益立竿见影。
2. **「会话由 host 持有、UI 只是视口」的架构是对的**，但所有承诺（跨 UI 存活、30 分钟回收、失焦不遮内容）都没有在界面上兑现成可见信号——二级的 U-5~U-13 全部是「把已有能力接到界面 + 让状态可见」，不依赖新架构。
3. **多数建议只需把已存在的能力接线**：`merge` 纯函数、scrollback 重放、`dmsTabDot` 样式、`stateLabel` 计算、`ServerPicker` 组件、`.dmsErr` 错误面——全部已实现未使用。
4. 建议按 U-1 → U-2 → U-3/U-4 → U-5 → 二级 → 三级的顺序推进；U-6/U-7 是「边聊边盯」体验的天花板，U-8/U-9 是信任基础。
